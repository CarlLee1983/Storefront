# 退款逐案記錄，同張訂單逐筆執行

部分取消與部分退貨可能讓同張訂單產生多次退款，無法再以付款的一個「已退款」欄位表達所有金額與進度。依訪談 Q16，每個核准案件各自記錄退款，同張訂單逐筆執行；前筆結果未確定時後筆等待，重試沿用同筆退款紀錄，累計退款不得超過實收款項。

這選擇了逐案可追溯與較簡單的款項核對，放棄同張訂單多筆退款並行或合併待退案件的效率。依 Q14，取消核准後就停止履約並釋放保留，不能因退款失敗恢復出貨；退款失敗須在自己的進度中繼續處理。

可重試或結果未明的退款仍佔用額度，不能因一次失敗而將同一筆可退金額重新承諾給其他案件。Q19 已確認：明確失敗時可讓後筆前進，失敗那筆仍保留額度並列待處理；結果不明時先補查，後筆等待。重試也不可與同張訂單其他退款並行，避免一筆已確認失敗的退款永久阻擋其他案件，同時維持金額核對的單純性。

這是尚未實作的目標模型；不指定資料表、佇列或重試次數。舊金流介面只有整筆退款，必須連同 App 的付款／退款紀錄與模擬閘道一起調整，避免只改顯示文字。
