## 已確認決策

- Q1：本輪聚焦後台共用導覽與頁面框架，涵蓋功能分組、所在位置提示及手機選單。各功能頁內的表單與操作流程另行判斷。
- Q2：首要問題是找不到功能或功能分組不直覺；改善成效須以功能是否容易找到為核心，而非只減少導覽占用空間。
- Q3：桌機／筆電為主要操作裝置，手機偶爾使用；桌機優先，手機仍須能完成必要操作。
- Q4：採用下列四組功能分類；退款待辦歸入「款項與憑證」。
- Q5：桌機採固定左側導覽，群組與文字入口預設展開；手機以選單按鈕開啟抽屜，兩者使用相同分類。
- Q6：以訂單管理作為進入後台的第一站。本輪不新增跨功能待辦總覽。
- Q7：側欄持續標示目前頁面所屬功能；內容上方提供可返回列表的麵包屑，例如「訂單管理 › 訂單編號」。從列表進入明細或編輯後，返回時保留原搜尋、篩選與頁碼。
- Q8：本輪以分組與完整文字解決查找問題，不新增功能搜尋、我的最愛、選單待辦數字或只顯示圖示的側欄模式。
- Q9：採用下列驗收條件；視覺沿用現有色彩與字型，調整導覽與內容區配置。
- 沿用既有領域定義：操作者為「管理員」，只有一種後台角色；參見根目錄 `CONTEXT.md`。

## 驗收條件

- 桌機能直接辨認四個群組，並從左側導覽找到全部 12 個入口。內容過高時仍須能捲動取得所有入口。
- 進入後台的第一站為訂單管理；商品列表、新增、編輯及返回列表仍可正常操作。
- 明細與編輯頁標示正確所屬功能，提供可返回列表的麵包屑；從有搜尋、篩選或頁碼的列表進入後，返回原列表條件。
- 375px 手機可開啟抽屜並找到全部功能，選取功能後正常到達頁面，頁面沒有非預期的水平溢出。
- 保留鍵盤操作、清楚焦點、至少 44 × 44px 點擊目標與無障礙檢查。抽屜須可用鍵盤開關，關閉後焦點回到開啟按鈕；關閉時其中連結不能取得焦點。
- 保留跳到主要內容、後台 `noindex`、前往前台連結與各功能既有行為。
- 沿用既有色彩與字型；不以這次導覽調整變更訂單、庫存、付款、退款等業務規則。

## 首頁與返回路徑的落地方案

以下是依 Q6、Q7 整理、並經使用者最後確認的落地方案：

- `/admin` 改為前往訂單管理 `/admin/orders`；商品列表移至 `/admin/products`。既有商品新增及編輯網址保留。原本收藏 `/admin` 的人，之後會先看到訂單管理。
- 目前 `/admin` 同時承載商品列表 GET、搜尋／篩選／分頁與商品操作 POST。搬移時須一起更新表單、分頁、儲存後轉址、取消與返回連結，以及測試與 seed harness 的商品入口；不能只改選單文字或將舊商品操作導向訂單頁。
- 商品與訂單列表目前都沒有將原列表條件帶入編輯／明細後的返回連結。Q7 因此包含新增跨頁返回狀態的行為，需要少量調整列表與明細／編輯頁的連結，不改頁內業務流程。
- 從列表進入時保留該列表已有的搜尋、篩選與頁碼；直接開啟深層頁面而沒有來源條件時，返回所屬功能的預設列表。返回目的地限所屬後台列表，不接受任意外部目的地。
- 既有頁面之間的相關案件捷徑保留，例如從訂單前往退款及發票待辦；主要導覽每項功能只有一個所屬群組。

1. 整理共用導覽資料、群組及目前區域辨識，實作桌機側欄與手機抽屜。

4. 驗證 375px 手機、1280px 桌機及版型切換附近的寬度；涵蓋全部入口、深層頁面、鍵盤操作、抽屜焦點與無障礙。
5. 執行相關回歸與 repository gates（typecheck、coverage、E2E），更新驗收文件。既有單行 header 的版型斷言依新設計更新，操作與無障礙保障保留。
