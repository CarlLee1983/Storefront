# 家居選物商城擴充規格

更新日期：2026-10-02。狀態：Q1–Q31 建議均經使用者回覆「全部同意」確認，產品決策已收斂。本文件整理目標規格與交付建議；尚未開始或授權產品實作、真實服務串接及部署。

## 目標與範圍

建立單一商家的家居選物商城演練，涵蓋家具、燈具、器物的購物、營運、履約、售後及故障復原。金流、物流、發票與通知使用模擬服務，但須有可操作、可核對的完整流程，不能只提供成功畫面。（Q1、Q2、Q24、Q31）

[原功能缺口評估](../research/commerce-gap-assessment-2026-10-02.md)保留真實營運假設及程式證據；其中真實商家申請、金流與發票上線等 P0 不等於本輪演練的交付順序。[官方能力研究](../research/commerce-capability-reference-2026-10-02.md)提供比較依據，不指定本案必須採用哪家供應商。

## 商品與顧客

- 商品保留共同介紹、尺寸、材質、保養資訊及圖庫，由管理員維護。最多兩個可自訂名稱的選項維度，只建立實際販售組合；無選項商品有一個預設變體。變體各有售價、原價、庫存、配送類型，可停賣並保留歷史。（Q3、Q9、Q26、Q27）
- 同商品變體共用最多 8 張圖片，第一張為預設封面；變體可指定其中一張供選取時顯示。訂單繼續使用目前商品圖片，不封存歷史圖檔。（Q9、Q22）
- 列表顯示未停賣變體的售價範圍；其中有特價變體時標示「有特價選項」，選定後顯示該變體確切價格及庫存。有貨篩選要求至少一個未停賣變體的可售量大於零。全部變體停賣時不得顯示可購買報價或允許結帳。（Q27；最後一項為停賣規則的推導）
- 原價是高於售價的劃線參考價，結帳及退款依實付金額。維持新台幣整數元、商品價格含稅；折扣百分比四捨五入不到 1% 時不顯示百分比標籤。（Q18 及沿用既有政策）
- 商品新建預設下架、重新上架時間、分類及預設排序規則沿用現況。補基本 Product 結構化資料與 sitemap；內容必須符合可見商品、價格及供貨狀態。（Q30）
- LINE／Google 登入身分維持分開；顧客首次結帳前須獨立取得並驗證聯絡 email。提供帳戶頁、聯絡 email 管理、地址簿。購物車按變體區分，仍保存在單一瀏覽器，未登入可使用，結帳須登入。（Q4、Q12、Q30）

## 下單、配送費與交易快照

- 一般宅配與大型配送限台灣本島；配送類型設於變體。初始演練費用為一般 NT$100、大型 NT$600，管理員可調整後續訂單的費率。同類一張訂單只收一次，混合類型各收一次；商家分批出貨不追加費用。大型配送由管理員記錄與顧客議定的預約時段。（Q10、Q26）
- 訂單快照商品名稱、變體選項、實付單價、配送類型、各類實收運費及收件資訊。商品、費率或地址簿之後改動不改寫既有交易。（Q22）
- 保留目前價格比對、防超賣、結帳冪等、付款期限與事件去重。待付款訂單仍只能整單取消，要改內容須重新下單。遲到付款依 [ADR 0001](../adr/0001-late-payment-reclaims-or-refunds.md) 重新取得完整保留或退款；取消後遲到付款仍退款，不因本次擴充恢復履約。（Q8 及沿用既有交易原則）

## 庫存與分批履約

可售數量 = 實體在庫 − 不可售數量 − 待付款保留 − 已付款待出貨保留。（Q7、Q13）

| 業務事件 | 必須成立的數量變化 |
| --- | --- |
| 訂單成立 | 增加待付款保留；不減實體在庫 |
| 付款成功 | 待付款保留轉已付款保留；不改實體在庫 |
| 待付款逾期或取消 | 釋放待付款保留 |
| 已付款取消申請成立 | 凍結申請數量的出貨資格，仍占原已付款保留，不重複扣可售量 |
| 取消核准／拒絕 | 核准釋放相關保留並停止該數量履約；拒絕恢復可交運資格 |
| 真正交付物流 | 扣相應實體在庫，消耗相應已付款保留 |
| 物流仍持有原貨物，再次配送 | 不新增出貨數量、不二次扣庫 |
| 退貨或物流退回實際入倉 | 增加實體在庫及不可售數量 |
| 入倉檢查合格 | 不可售轉可售，實體總數不變；損壞品繼續隔離 |
| 隔離品報廢移出 | 同時扣相應實體在庫及不可售數量 |
| 確認遺失 | 無實物返回，不回補庫存 |

管理員的補貨、盤損等既有庫存調整仍以增減及原因記錄，不直接覆寫數字。庫存流水須能解釋每筆變動；調整後不能讓已承諾訂單的數量失去追蹤。（Q23）

一張訂單可有多個出貨批次，各記錄明細數量、物流單號、配送進度與實際送達時間。支援送達、失敗後再次配送、物流退回、確認遺失。回倉檢查後退款；遺失退款但不補庫。這兩種終止履約後要再購買須重新下單，不從同單補寄。（Q5、Q20）

取消申請與交運以先有效成立者為準：申請先成立就禁止交運該數量；已交運則走退貨。核准取消後，即使退款失敗也不恢復出貨。每一購買數量的出貨、取消、退貨及退款須可核對，不得被不同案件重複占用。（Q8、Q14）

## 售後與退款

顧客從訂單選擇明細與數量提出退貨；管理員審核、安排收回、記錄檢查後退款。收回運費由商家負擔，可再售數量才恢復可售。換貨以退貨退款後重新下單完成。（Q6、Q11、Q15）

自助退貨以每批實際送達的隔日起算 7 天。逾期、沒有可靠送達日期或瑕疵需求仍有人工受理入口，不能只因自助窗口關閉就自動否決。這是本輪演練政策，不是對所有交易情況的法律判定。（Q28）

### 運費退款優先規則

| 原因 | 商品款 | 該配送類型原實收運費 |
| --- | --- | --- |
| 顧客取消／退貨 | 核准取消或完成收回檢查的相關數量，按原實付單價 | 同類全部數量均取消或完成退貨檢查才退一次；部分不退（Q15） |
| 物流退回並完成檢查進入退款／確認遺失 | 只退受影響數量，按原實付單價 | 任一筆成立就退該類全部原實收運費一次，即使同類其他商品已送達（Q25） |
| 暫時配送失敗後送達 | 無退款 | 無退款（Q25） |

Q25 是優先於 Q15 的異常條款。取消與退貨混合使同類全數退出履約，也符合 Q15；待審、在途及待檢尚未符合。任何觸發順序下，同一類原運費最多退一次；已退或已承諾退款的費用不能再開第二筆。費率後來調整不影響此計算，舊單原實收運費為零就退零。（Q15、Q22、Q25 的一致性條件）

### 逐案退款與金額約束

- 每個核准案件獨立記錄退款金額及進度；同單逐筆執行，重試沿用同筆紀錄，顧客可查每筆結果。（Q16）
- 結果不明先查證並阻擋同單後續退款；明確失敗可讓後筆前進，原筆仍保留額度並列待辦，重試也不得與同單其他退款並行。（Q19）
- 成功退款加所有仍可執行的退款承諾不得超過實收。待執行、結果未明、失敗但可重試都占用額度；不能因失敗重新承諾同一商品數量或運費。若正式終止並釋出額度，該請求不能直接再重試。（Q16、Q19 的一致性條件）
- 退款與取消履約、退貨檢查、庫存回補、發票折讓分開記錄；任一流程成功不代表其他流程已完成。（Q11、Q14、Q21）

## 發票、通知與進度

收款成功產生原收款金額的模擬發票，成功退款產生折讓，顧客可查原額、累計折讓與剩餘金額。開票或折讓失敗須可補辦，不阻擋已確認的付款、出貨或退款。若退款先於延遲開票成功，先保留退款事實，再於原票完成後補折讓；相同收款／退款重送不得重複產生憑證。（Q21）

驗證及交易通知送入模擬信箱。顧客只能讀自己的信箱；管理員可看投遞結果及演練控制，驗證連結不公開。變更聯絡 email 完成驗證後，新舊訂單的後續通知及憑證重寄採目前已驗證地址；每次投遞保留實際收件地址，不改寫既有信件或憑證內容。（Q12、Q17、Q24）

通知事件包括下單、付款結果、取消審核、出貨與配送異常、退貨審核、退款結果、發票完成。通知對應業務狀態變化，不把每次技術重試都當成新的顧客事件。投遞失敗可查及重送。（Q29）

訂單畫面分別顯示付款／退款、各出貨批次、售後及發票進度，搭配事件時間線，能同時表達「部分送達、部分取消、退款待處理、發票待補」。這項呈現要求不指定資料表或狀態 enum。（Q29）

## 管理員與演練控制

單一管理員角色，提供訂單搜尋、分頁、匯出、客服備註、取消／退貨審核、退款待辦、庫存流水、低庫存提醒。重要操作保留操作者、時間及原因。超過最新 200 筆的舊單仍須能找到並處理。（Q23）

金流、物流、發票與通知的模擬服務須能演練失敗、延遲、重送及通知遺失，透過補查、重試或有紀錄的人工待辦恢復。成功頁面不取代服務結果或交易事實。顧客、管理員與演練控制的權限須有檢查，不能藉查詢別人識別碼讀取訂單、地址、售後或信箱。（Q24、Q31）

## 本輪排除

- 真實金流、物流、郵件、電子發票上線及商家申請；不以正式收款或部署為完成條件。
- 訪客結帳、帳號合併、跨裝置購物車。
- 超商取貨、跨境、組裝、樓層加價、司機排班與配送容量系統。
- 同單補寄、直接換貨、替換商品保留與補退差價。
- 統編、載具、捐贈；只演練一般個人消費發票。
- 優惠券、滿額折扣、促銷排程、點數、收藏、評價、推薦、CMS、進階行銷。
- 多商家、後台分權、採購、多倉、進階營運分析。

## 現行程式與遷移邊界

以下是靜態程式證據，不表示目標功能已存在；詳細盤點見研究文件。

| 邊界 | 現況 | 必須一起處理的目標 |
| --- | --- | --- |
| 販售單位 | `apps/app/src/catalog/schema.ts` 價格、在庫在商品；`orders/input.ts` 限同商品一筆明細 | 變體涵蓋購物車、價格校驗、庫存、訂單、後台；同商品不同變體可分別購買 |
| 扣庫時點 | `payments/queries.ts` 付款扣庫；`orders/queries.ts` 出貨不扣 | 付款、出貨、保留、可售量及舊資料協調切換，避免雙扣或憑空增加可售 |
| 履約與進度 | 整單一次 `paid → shipped`；五種訂單狀態 | 明細數量的批次與售後記錄，分開多種進度；不能只新增顯示文字 |
| 退款 | `payments/refund.ts` 僅三類付款異常；App 缺一般退款復原；閘道整筆退款 | App 與模擬閘道一起支援多筆部分退款、查證、同單互斥、額度與重試 |
| 聯絡與憑證 | LINE 識別 email 不可投遞，未實作驗證信、通知或發票 | 聯絡 email 獨立驗證，模擬信箱隔離及可復原的憑證流程 |
| 後台 | `orders/admin-queries.ts` 最新 200 筆及狀態篩選 | 搜尋、分頁、匯出、客服與營運待辦，不因清單上限漏掉舊單 |

Q22 已確認保留式遷移：舊商品轉預設變體；舊單保留實付單價、既有交易金額及免運條件。舊系統在付款扣庫，舊已付未出貨數量需加回實體在庫並同時建立已付款保留，不能增加可售量；已出貨數量不再加回。未知物流單號、送達日期與交易快照缺值不得編造；沒有可靠送達日的退貨走人工入口。

實作前必須證實的技術條件：

1. 用既有資料與對應庫存證據驗證遷移換算，列出不一致或無法推定的例外，準備備份、可重跑驗證及回復方式。狀態不是實際盤點的替代品；變更後恢復舊版須避免抹掉新交易。
2. 模擬閘道能表達同收款多次部分退款、同筆重試、結果查證及金額上限；App 能驗收同單互斥與明確失敗後續處理。
3. 實際送達、退回入庫、檢查、運費返還義務與憑證／通知結果，在漏通知和重送後仍可對帳。

這些是實作設計及驗證工作，不是新的產品決策。API、資料表、排程與重試門檻按既有架構細化，不預先新增服務或套件。

## 依賴順序與交付切片

以下為依已確認規格整理的執行建議；每片包含可操作的顧客／管理員入口、持久資料、必要遷移及行為測試，不能以只有後端或展示畫面交差。（Q31）

| 順序 | 可驗收切片 | 依賴與完成結果 |
| --- | --- | --- |
| 1 | 變體商品與完整選購 | 商品管理、尺寸材質保養、選項圖片、價範圍／特價／有貨、停賣、變體購物車與結帳及舊商品預設變體；補基本商品 SEO。此片保留現行扣庫時點，先完成變體邊界，不宣稱已達目標實體在庫語意 |
| 2 | 帳戶、已驗證聯絡方式與通知基礎 | 可與第 1 片獨立設計；顧客管理聯絡 email／地址簿，驗證與下單付款通知在隔離的模擬信箱可查可重送，管理員可查投遞結果 |
| 3 | 實體庫存、配送計費與分批交運 | 依第 1、2 片；協調切換付款／出貨扣庫與舊資料，完成一般／大型計費、預約、庫存流水、正常分批送達及顧客進度；取消與交運的數量邊界需預先按本規格設計 |
| 4 | 售後退款與物流異常復原 | 依第 3 片；App 與閘道一起完成退款核心、取消凍結與審核、退貨檢查、兩種運費規則、物流退回／遺失、退款待辦及通知。此片先建款項一致性再接各入口，片內以可驗收小步推進 |
| 5 | 憑證與營運收尾 | 依第 4 片；模擬發票／折讓及補辦，完成各進度與時間線、其餘通知、訂單搜尋／分頁／匯出、客服備註及低庫存提醒。可獨立的後台搜尋工作可提前，不阻擋主交易邊界 |
| 6 | 全流程演練與整合驗收 | 使用同一批資料完成下列矩陣；覆核遷移、故障復原、顧客隔離、手機／桌機、既有功能回歸及 repo gates；同步 FAQ、配送、退貨與發票文案，移除不符合已實作流程的承諾 |

每片須能驗收當片提供的行為，整體完成仍須通過第 6 片；中間切片不是正式商店上線聲明。導入新流程時移除被取代的舊路徑，避免同一交易同時適用兩套規則。

## 驗收矩陣

| 編號 | 情境 | 可觀察結果 |
| --- | --- | --- |
| A1 | 不同變體同時選購、價格變動、停賣、售罄、無選項商品 | 各變體價格／數量獨立；列表與選取後資訊一致；結帳重新檢查；停賣與缺貨不繼續成交 |
| A2 | 兩顧客競購最後庫存、付款、逾期與遲到付款 | 不超賣；保留／實體符合事件表；既有遲到付款重新保留或退款原則成立 |
| A3 | 混合配送與改費率／地址／商品資訊 | 一般與大型各收一次；分批不加收；舊單快照及實收不變 |
| A4 | 取消申請與交運同時發生、拒絕及核准 | 僅先成立動作取得相關數量；取消待審不可交運；拒絕解凍；核准後退款失敗仍不恢復出貨 |
| A5 | 每批不同送達日、7 天邊界、日期未知、逾期及瑕疵 | 窗口逐批計算；未知或例外可人工受理；可退款數量不因多案重複累計 |
| A6 | 退回良品、損壞品、報廢；物流重送與遺失 | 實物、不可售、可售及庫存流水對得上；重送不雙扣、遺失不補庫 |
| A7 | 同類部分取消、部分退貨，最後全部退出；部分物流遺失 | 一般部分售後不退費、全退出退一次；物流例外即使同類部分送達也退全類原費一次；兩規則先後觸發仍不重退 |
| A8 | 多筆退款、明確失敗、逾時結果不明、重試與重複回呼 | 明確失敗保留額度且後筆可前進；不明先查且阻擋後筆；同單不並行，金額與數量上限均成立 |
| A9 | 付款或物流通知遺失、顧客付款後關窗 | 能查回實際結果並補齊本地進度，不能只依賴顧客返回頁面；無法自動恢復時有可操作待辦 |
| A10 | 發票延遲／失敗、退款先成功、折讓失敗與重送 | 不阻擋交易；原票完成後補齊折讓，原額減累計成功折讓為餘額；沒有重複憑證 |
| A11 | 換 email、重寄舊訂單通知、投遞失敗、跨顧客識別碼 | 新投遞用目前已驗證地址，歷史不改寫；可重送不偽造業務新事件；無法讀取別人的訂單、地址、售後或信箱 |
| A12 | 超過 200 筆訂單、客服／庫存異動、低庫存 | 舊單能搜尋、分頁、匯出；重要操作追溯人／時間／原因；流水可核對，低庫存可見 |
| A13 | 舊待付款／已付未出貨／已出貨／取消訂單遷移 | 預設變體、原交易金額、免運及保留不丟失；無額外可售；未知物流不偽造；演練驗證與回復程序 |
| A14 | 桌機及手機完整路徑、商品 SEO 與整合 gates | 核心操作可用，結構化資料與可見價格庫存一致；型別、覆蓋率、E2E 及既有驗收通過 |

### 同一訂單的整體演練

初始在庫：一般配送燈具 3 件，每件 NT$1,000；大型配送桌子 1 件，NT$6,000；無其他保留或不可售品。商品小計 NT$9,000，加運費 NT$100 + NT$600，收款 NT$9,700。

1. 下單保留全部數量；付款後轉已付款保留，實體仍為燈具 3、桌子 1。
2. 交運燈具 2 件，另 1 件申請並核准取消。該筆退款 NT$1,000，燈具實體剩 1、沒有保留、可售 1；一般運費暫不退。
3. 已送達的 2 件燈具中退回 1 件，檢查合格後退款 NT$1,000。燈具實體及可售均為 2；顧客仍保有 1 件，一般運費 NT$100 保留。
4. 桌子另批交運後確認遺失，退商品 NT$6,000 與大型原運費 NT$600；桌子實體與可售均為 0，沒有回補。
5. 三筆退款共 NT$8,600；收款剩額 NT$1,100，等於保留的一件燈具與一般運費。模擬發票原額 NT$9,700，成功折讓合計 NT$8,600，餘額 NT$1,100。
6. 在相同流程注入第一筆退款明確失敗再重試、延遲開票、折讓與通知失敗補辦，最後金額及庫存結果不變，時間線保留各次業務事實。結果不明阻擋後筆及其他配送費交叉情境另依 A7、A8 驗收。
